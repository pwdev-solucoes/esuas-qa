CA37 — Criação de camada válida (HU-CAM-01) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que sou Administrador e as bases geográficas primárias estão homologadas, Quando informo nome, descrição, critérios de busca e forma de representação e salvo, Então a camada é criada com status de rascunho e passa a constar no catálogo.

Como foi testado: POST /api/geo-layers como super admin (Sanctum stateful) com nome, descrição, criteria.vulnerabilities=[receives_pbf] e representation=heatmap — Anexo A.

Resultado observado:
  • HTTP 201; camada criada com status=draft e uuid próprio; aparece no GET /geo-layers.
  • Pest: suíte GeoLayerController cobre criação e catálogo (Anexo B).
  • UI: form em página '/app/geo-layers/nova'; camada 'Cobertura SCFV — evidência E2E' criada e listada como Rascunho.

CA38 — Bloqueio por dados obrigatórios (HU-CAM-01) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que estou criando uma camada, Quando tento salvar sem nome ou sem ao menos um critério de busca, Então o sistema bloqueia a ação e indica claramente os itens pendentes.

Como foi testado: POST /api/geo-layers sem name e com criteria={} — Anexo A.

Resultado observado:
  • HTTP 422 na API com itens pendentes.
  • UI: mensagens de campo 'Informe o nome/descrição da camada' e 'Informe ao menos um critério efetivo' bloqueiam o salvar.

CA39 — Nome duplicado (HU-CAM-01) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que já existe uma camada com determinado nome, Quando tento salvar outra camada com o mesmo nome, Então o sistema bloqueia e informa que o nome já está em uso.

Como foi testado: POST /api/geo-layers com o mesmo nome em CAIXA ALTA (variação de caixa e acentos) — Anexo A.

Resultado observado:
  • HTTP 422 na API (variação de caixa).
  • UI: 'Já existe uma camada com este nome.' exibido no campo ao tentar criar 'COBERTURA SCFV — EVIDÊNCIA E2E' (caixa alta).

CA40 — Pré-visualização por tenant de referência (HU-CAM-01) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que criei uma camada em rascunho, Quando aciono a pré-visualização escolhendo um município de referência, Então o sistema exibe a representação da camada sobre o mapa daquele município conforme os critérios definidos.

Como foi testado: Decisão do PO (2026-07-04): preview usa tenant único de referência (combobox). POST /geo-layers/{uuid}/preview com tenant_uuid do tenant 1 (Fortaleza) — Anexo A (inclui adendos).

Resultado observado:
  • Cenário negativo: tenant sem município com geometria homologada → HTTP 422 com mensagem clara.
  • Cenário positivo: HTTP 200 com city_geometry de Fortaleza, total=6, by_sector com 2 setores fixture e 6 pontos anônimos (chaves só lat/lng/count — sem PII).
  • Trilha: event=previewed com properties={tenant: uuid} (LGPD).
  • Nota de ambiente: geometria/setores de Fortaleza estavam is_active=false no banco e2e (efeito replace-all da sync #9868) e foram reativados — artefato de massa, não bug de produto.
  • Nota ao PO (revisão Etapa 02, severidade média): no preview de 'Delimitações', o admin desenha polígono municipal + pontos + tabela por setor; o choropleth por setor é renderizado no painel do tenant (o contrato manager não expõe geometrias de setor).

CA41 — Consulta sem permissão de edição — Operacional Global (HU-CAM-01) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que sou Operacional Global, Quando acesso o catálogo de camadas, Então visualizo a lista com status e público de cada camada, sem comandos de criação, edição ou publicação.

Como foi testado: Lado servidor: RoleSeeder concede só geo-layers.index/show ao papel admin_operador; escrita → 403 (Pest, Anexo B). Evidência visual da UI deferida à Etapa 02 (admin).

Resultado observado:
  • Pest: admin_operador lê catálogo/detalhe; os 7 verbos de escrita retornam 403.
  • UI: logado como Operacional Global (papel admin_operador), o catálogo não exibe 'Nova camada' e o menu Ações só traz 'Ver detalhes'; rota /nova responde 403 Acesso negado.

CA42 — Publicação global (HU-CAM-02) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que tenho uma camada em rascunho válida, Quando publico com público 'todos os tenants', Então a camada passa a aparecer na barra lateral do Painel de Georreferenciamento de todos os tenants ativos, desligada por padrão.

Como foi testado: POST /geo-layers/{uuid}/publish com audience=global; em seguida GET /api/client/geo-panel/layers como master do tenant 1 — Anexo A.

Resultado observado:
  • HTTP 200: status=published, published_at gravado.
  • Listagem do tenant mescla 3 built-ins + camada custom (kind=custom, builtin=false) — fecha também o CA29 da HU-GEO-01.
  • UI (client): camada global 'Famílias beneficiárias do PBF' ligada no painel do tenant renderiza mancha (heatmap OL) sobre Fortaleza. Nota ao PO: o heatmap OL usa o gradiente default (a cor/palette da camada é aplicada em markers/boundaries; opacidade respeitada).

CA44 — Bloqueio sem base geográfica homologada (HU-CAM-02) ATENDIDO · navegador + automatizado

CA45 — Alteração de público com efeito imediato (HU-CAM-02) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que uma camada está publicada para tenants específicos, Quando altero o público incluindo ou removendo tenants, Então a disponibilidade da camada é atualizada imediatamente nos painéis dos tenants afetados.

Como foi testado: PATCH /geo-layers/{uuid}/audience incluindo o tenant 1; próximo GET do tenant 1 sem nenhuma outra ação — Anexo A.

Resultado observado:
  • 'L2 visível p/ tenant 1?' passa de False para True no fetch imediatamente seguinte — visibilidade resolvida em leitura, sem cache/materialização.

CA46 — Isolamento de dados na camada (HU-CAM-02) ATENDIDO · navegador + automatizado

Critério (Gherkin): Dado que uma camada foi publicada globalmente, Quando um tenant a liga em seu painel, Então visualiza apenas os dados do seu próprio escopo, sem qualquer dado de outro tenant.

Como foi testado: GET /api/client/geo-panel/layers/{uuid}/data com X-Tenant-UUID do tenant 1; camada draft consultada pelo tenant — Anexo A.

Resultado observado:
  • Dados executados sob o tenant consumidor: total=6, pontos anônimos (lat/lng/count).
  • Camada draft/não visível → HTTP 404 (nunca 403 — não vaza existência).
  • Pest: 2 tenants no mesmo município com massas próprias → pontos 100% disjuntos; tenant_id vem do header validado pelo EnsureTenantScope (merge sobrescreve forjado).
  • UI (client): render por representação sob o escopo do tenant — choropleth por setor com intensidade graduada (4/2 famílias, cor do style #7c3aed) e marcadores anônimos graduados. Nota: no engine Leaflet o heatmap tem paridade mínima (círculos difusos), registrado como débito de paridade visual.

RN06/P5 — Ciclo de vida sem exclusão — inativar/reativar/405 ATENDIDO · navegador + automatizado

Critério (Gherkin): Camadas não são excluídas definitivamente enquanto houver histórico de uso — apenas inativadas (RN06). Recurso sem DELETE (405).

Como foi testado: POST inactivate → fetch do tenant; POST reactivate → fetch; DELETE /geo-layers/{uuid} — Anexo A.

Resultado observado:
  • API: inativada some do fetch do tenant; reativada volta ao público configurado; DELETE → 405.
  • UI: dialog de inativação com aviso de efeito imediato (CA48); dialog de reativação (CA49); listagem reflete Inativa → Publicada mantendo público Global.
  • UI (client, CA48 ao vivo): com a camada LIGADA no painel, o Administrador a inativa; ao reabrir a barra de camadas o cliente reconcilia, desliga a camada e exibe o toast 'não está mais disponível — removida ou inativada pelo administrador' (toggle some da sidebar).
  • UI (client, CA49): reativada pelo Administrador, a camada volta à sidebar DESLIGADA (refetch de dados garantido pelo descarte de cache).
